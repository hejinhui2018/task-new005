# 语言路由台 · Language Routing Console

为国际会议同传负责人设计的**语言路由调度台**。主讲人切换语种或译员临时离席时，
现场可以立刻看清：哪些耳机频道仍能正常收听、走的是哪条路径、占用了哪些译员的
几个席位、哪些频道已经超载或断路、原因是什么。

纯前端实现：**React 18 + TypeScript + Vite**，所有计算在浏览器本地完成，
无后端、无网络请求、无外部运行时服务。

## 调度模型

### 三种节点

- **语种节点**：主讲声源所在语种 + 各目标语种；
- **译员节点**：有明确的源语种、目标语种和**席位数**（可同时承担的频道数）；
- **听众频道**：对应一种耳机语言，带优先级（数字越小越优先，`P0` 最高）
  和允许使用的中继语言列表。

### 路径规则

- 频道可以**直译**（主讲语 → 目标语，1 跳），也可以经过**一种中继语言**
  （主讲语 → 中继语 → 目标语，**最多两跳**），不允许三跳；
- **循环路径一律拒绝**：中继语不得等于主讲语或目标语，同一路径上同一
  译员不得重复出现（内部以「已访问语种集合」判定）；
- 离线（离席）译员不参与任何路径；源语种等于目标语种的自环译员无效；
- 每个被覆盖的频道占用所选路径上**每位译员各一个席位**，
  任何译员的占用数不得超过其容量；放不下整条路径时**不做半条中继**。

### 分配策略（确定性）

1. 频道按优先级升序处理，同优先级按 id 排序；
2. 候选路径按固定顺序选择：**直译优先于中继**；同为中继时按频道声明的
   中继语言偏好；同等条件下**大容量译员优先**（把小容量备援舱留到最后），
   再按姓名、id 排序；
3. 取第一条「每一跳都还有剩余席位」的路径并占用；
4. 高优先级频道已占席位**不可被低优先级抢占** —— 容量不足时，
   系统确定性地保住高优先级频道。

### 三种频道状态（不仅靠颜色区分）

| 状态 | 含义 | 视觉/读屏编码 |
|---|---|---|
| `COVERED` 正常覆盖 | 存在一条已占用席位的完整路径 | 绿色左边条 + `✓ 正常覆盖` 徽标 |
| `OVERLOADED` 超载竞争失败 | 拓扑上有候选链路，但所有路径都被高优先级频道占满 | 琥珀色边 + **斜纹底纹** + `⚠ 超载竞争失败` + 原因码 |
| `BROKEN` 断路 | 在线拓扑上根本不存在合规链路（如中继第一/第二跳缺失） | 红色边 + **横纹底纹** + `✕ 断路` + 原因码 |

故障原因码（频道卡内直接展示，附中文说明与卡点语种对）：

- `NO_CANDIDATE` — 无直译也无合规中继；
- `NO_SPEAKER_RELAY` — 中继链第一跳缺失（主讲语 → 中继语无人）；
- `RELAY_TO_TARGET_MISSING` — 中继链第二跳缺失（中继语 → 目标语无人）；
- `DIRECT_FULL_RELAY_UNAVAILABLE` — 直译席位全部占满且无中继；
- `RELAY_BOTTLENECK` — 中继路径某一跳席位被占满。

## 内置演练场景

中文主讲的国际会议，需要**英语、法语、日语**三个外语频道，
其中**法语、日语依赖英语中继**：

| 译员 | 语种对 | 容量 | 初始状态 |
|---|---|---:|---|
| 张伟（主力） | zh→en | 3 | 在岗 |
| 李娜 | en→fr | 2 | 在岗 |
| 佐藤 | en→ja | 2 | 在岗 |
| 王强（备援） | zh→en | 2 | 离席 |
| 松下（日语直传备援） | zh→ja | 1 | 离席 |

顶部演练按钮一键切换四个阶段（也可手动操作译员卡）：

1. **初始**：英语直译；法语、日语经英语中继。张伟同时服务三个频道（3/3 席）。
2. **① 主力离席**（关闭张伟）：英/法/日全部断路 —— 英语 `NO_CANDIDATE`，
   法/日 `NO_SPEAKER_RELAY`（中继第一跳 zh→en 缺失），节点图上受影响连线
   变为灰色虚线，语种节点出现 `✕ 断路` 角标。
3. **② 启用备援（2 席）**（召回王强）：系统按优先级**确定性保住 P1 英语**
   （直译占 1 席）与 **P2 法语**（中继再占 1 席）；王强 2/2 满舱，
   **P3 日语超载**，卡片斜纹显示 `RELAY_BOTTLENECK` 并点名 zh→en 这一跳。
4. **③ 加直译恢复**（再召回松下 zh→ja，1 席）：日语改走一跳直译，
   不再争抢王强席位，**四个频道全部恢复覆盖**。

> 可以在阶段三手动把日语频道的优先级改到法语之前，验证保住的频道会确定性
> 对调 —— 这就是「优先级驱动容量竞争」。

## 界面操作

- **节点图（左）**：主讲语在最左，直译可达语种居中，需中继的语种在右；
  绿色粗线为正在传声的路径并标注实时占用（如 `2席/2`），琥珀色表示该译员
  已满载，灰色虚线表示离席译员。
- **频道面板（中）**：每个频道一张卡片，展示实际路由链（声源 → 译员[席位]
  → 耳机）、中继标记、故障原因、未采用的备选路径；可修改优先级与允许的
  中继语言（勾选即生效，系统立即重算）。
- **译员面板（右）**：每位译员一张卡，席位格逐格显示占用；可一键
  在岗/离席、调整容量、删除，或用表单派遣新译员（姓名、源/目标语种、席位）。
- 所有状态都用**图标 + 文字 + 纹理/线型**三重编码，并带 ARIA 标签，
  色觉障碍或读屏场景同样可用。

## 项目结构

```
src/
  engine/            纯逻辑核心，无任何 React 依赖
    types.ts         领域模型与状态/原因码类型
    routes.ts        候选路径枚举：两跳上限、循环拒绝、确定性排序
    allocate.ts      优先级容量分配、三态判定与故障诊断
    index.ts
  data/preset.ts      内置中文主讲演练场景
  state/meetingReducer.ts  所有界面操作的 reducer（增删/上下线/容量/优先级）
  ui/
    GraphView.tsx    SVG 语种—译员节点图
    ChannelPanel.tsx 频道路由卡片与控制
    InterpreterPanel.tsx 译员席位卡片、新增表单
    layout.ts        节点图分层布局（BFS 深度 0/1/2）
  __tests__/
    routes.test.ts      路径选择、两跳上限、循环拒绝、确定性排序
    allocate.test.ts    容量竞争、优先级抢占、断路诊断、故障重路由
    scenario.test.ts    内置场景四阶段端到端断言
    app.test.tsx        界面演练按钮与状态渲染冒烟测试
```

引擎是纯函数（`allocate(meeting)` 同输入必同输出），不依赖 DOM，
因此所有路由规则都可以在命令行以毫秒级速度测试。
